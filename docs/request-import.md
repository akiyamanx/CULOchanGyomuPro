# 依頼書・訪問先一覧の追加取込 — 2026-10-14

## 利用手順
訪問・ルート →「Excel・依頼書を取り込む」→ ファイルを選択 → 登録先の月と内容を確認・修正 → チェックした分を追加登録。
ExcelをCSVへ変換する必要はない。新しい月を選ぶと月別一覧を作成する。既存の訪問先・訪問順・ルート・アポ状態は上書きしない。

## 対応範囲
- DP-400月次メンテナンス一覧：「設置先会社名」、県＋住所、営業所、型式、管理番号、電話、担当者、交換フィルター、備考。併記された部品注文書は訪問先として扱わない。
- ACWITHフィルター交換一覧：顧客名、県＋住所、電話、シリアル、備考。
- HWメンテナンス一覧：設置先名、住所、固定電話、機種、交換部材、履歴。
- ACWITH等の業務依頼個票：客先名、所在地、機種、台数、電話、チェック済み業務、工事予定日時、特記事項、SS。
- 修理の業務依頼個票：会社名、分割住所、複数連絡先、受付担当者、機種、管理番号、作業希望日＋時間、備考。
- PDF：文字入りPDFは文字抽出、画像PDFは端末内OCR。1ページを1候補として表示し、原本画像と読取文字も確認できる。
- CSVはUTF-8／Shift-JIS、Excelはxlsx／xls。複数ファイルと可視シートを読み込む。1回20ファイル・1ファイル20MB・PDF10ページまで。

一覧の挨拶・注意書きを訪問先にしない。住所だけ一致する別会社を勝手に統合しない。再取込の候補は未選択にするが、別作業として追加する場合は利用者が選び直せる。別シリアル・別機種は重複扱いしない。

日付だけの指定や複数日の工事は備考に原文を保持し、勝手に時刻を付けない。取込だけでは「アポ済み」にしない。PDFの読取間違い、手書き、原本にない支店名などは確認画面で補正する。管理番号を判読できない場合は空欄＋要確認メッセージ。

## 実装とデータの扱い
- `request-parser.js`：保存処理を持たない形式別解析・重複候補判定。
- `request-reader.js`：ファイル復号、Excel日付整形、PDF表示・OCR。PDF.js 5.6.205、Tesseract.js 7.0.0を必要時に読み込む。既存SheetJS 0.18.5を利用。
- `request-import.js`：確認・選択・修正・月指定・追加。登録は対象月の顧客配列へ1回の保存で行い、失敗時に候補を残す。保存完了後に地図を更新。
- Excelの日付にUTC変換を使うと日本時間で前日になるため、ローカル暦日を保持する。更新前スクリプトのHTTPキャッシュが残ったため、parser／readerの読込URLに版を付けた。
- 画像PDFのOCRはブラウザ内で行う。初回にCDNからライブラリ・言語データを取得する。依頼書をGemini等のAI APIへ送信しない。登録後の地図表示は既存のGoogle Maps設定に従う。
- 原本、抽出した実顧客情報、実電話番号、APIキーはリポジトリに含めない。公開するテストは架空データだけ。確認用ページは既存の保存キー分離を維持。
