# 駐車場領収書の提出

## 操作

「精算・PDF」→「駐車場代を取り込む・記録する」から写真を撮影、または複数の画像を追加する。1回20枚、1枚20MB以下。画像は長辺2400pxまでに整えて端末のIndexedDBへ保存する。現場で1枚ずつ追加しても既存明細は残る。元ファイル自体は変更しない。

Gemini設定済みの場合は保存後に日付・金額を読み取る。未設定・読取失敗でも写真は残り、手入力できる。既存のレシートタブで認識した駐車場の写真も取り込める。同じファイルの再追加はSHA-256、旧スキャナーからの再取込は画像一致で抑止。別々に撮影した同じ領収書は自動で同一視しない。

「写真を調整」で90度回転、±15度の傾き、四隅のドラッグまたは数値入力、白い紙の範囲を目安にした自動検出が使える。四隅を長方形に射影変換し、元の取込画像と補正後の画像を分けて保存する。「取込時の画像に戻す」は編集状態を初期化し、「調整を保存」で反映。「キャンセル」は保存済みの状態を維持する。紙の折れ・影・薄い印字を修復する機能ではない。

利用日を入力し「その日の訪問先から選ぶ」で同日訪問を表示する。対象は領収書の日付に対応する月で、現在開いている月を勝手に切り替えない。住所・入庫時刻と地図情報が使える場合は候補を並べ替えるが、自動確定はしない。登録直後でステータスが未確定でも、予定日が合う訪問を選べる。会社名・equipType（機種）・purpose（作業内容）を一緒に転記。不足は空欄を確認して入力する。同じ訪問に複数の領収書を付けられ、駐車場未利用の訪問先は操作不要。

## PDF

表示・出力する月、任意の日付、各写真の「PDFに載せる」で対象を選ぶ。日付未設定の写真は確認のため常に表示し、不足項目を残したままPDF出力しない。

A4横、標準は横3列×2段の6枚。4枚（2列×2段）も選べる。7枚目・5枚目は次のページ。各写真の下に、日付・訪問先会社名・機種と作業内容を横書きで配置する。長い会社名は折り返す。PDF上の写真は縦横比を保持して枠内へ収め、50〜100%で小さくする調整も可能。これ以上大きくしたい場合は余白を切り取るか4枚配置を使用。

全ページを画面確認してPDFを保存する。対応ブラウザでは共有ボタンも表示する。アプリから本部へのメール自動送信はしない。PDF選択と精算書への金額反映は独立しており、精算書は指定月の全駐車場明細を対象とする。

## 保存と互換性

- 書き込みは直列化し、IDBトランザクション完了後に保持データを更新。写真追加・編集失敗を成功扱いしない。
- 手入力はinput/change/focusoutで捕捉してまとめて保存。PDF生成前に未完了の保存を待つ。
- 既存明細のID・金額・拡張フィールドを保持する。古い写真のrotationもPDFに反映する。
- 旧仕様の機種欄に駐車場名が入っている場合、読取駐車場名と一致する明細はPDF前に修正を促す。
- 画像編集・PDF作成は端末内。AI読取は既存Gemini API、住所照合は既存Google Maps設定を利用。字体はNoto Sans JPを読み込む。
- 本番ルートは未反映。公開確認用フォルダだけを更新し、localStorageとIndexedDBを本番から分離する。

ブラウザの公開確認用画面で架空の領収書6枚を一括追加し、写真1枚の左右回転・傾き変更・初期化・自動余白検出・四隅数値修正・保存を確認。訪問予定CSVの2社から会社名・DP400/ACWITH・メンテナンス/修理の転記を確認。会社名などの手入力は初回ブラウザ検証で保存漏れを発見し、input捕捉とPDF前flushへ修正。再読み込みで6枚分の入力値が残ることを確認した。

6枚配置は1ページ、4枚配置は6枚で2ページの画面プレビューを確認。6枚PDFを実際にダウンロードし、1ページ・297×210mm・約475KBを確認。7枚目の追加と同じファイルの再追加を同時に行い「1枚追加・重複1枚」を確認。7枚のPDFは2ページ、両ページ297×210mmをダウンロードしたファイルで確認。長い会社名の折返し、日本語の表示、写真と説明の位置を画面で目視確認。

320px幅の実アプリiframeで、本文305/305px・写真一覧247/247px・写真編集ダイアログ286/286px（表示幅/内容幅）と横はみ出しなしを確認。
