# マップから出張費精算書までの修正

対象: CULOchanGyomuPro、基点 e3ae7cabd78a64c3195155c576c75759eba8efc3。
参照書式: CULOchanSEISANsho/index.html。ユーザー指定により駐車場代を独立列にする。

## 受入条件

- 選択した利用日とルートの訪問先・住所・計算済み走行距離を同じ日付の明細へ反映する。
- ETC CSVは引用符内のカンマを扱い、利用日ごとの高速代と枚数を反映する。同じCSVの再取込で二重計上しない。
- 駐車場明細は利用日ごとの専用欄へ反映する。反映を繰り返しても二重計上せず、金額変更も更新できる。
- 年を含む日付・取込情報・駐車場代・日別行先は下書きに保存し、旧下書きも読み込める。
- 専用書式は横向きA4。行先、日付、距離、高速代、駐車場代、その他、各合計を出力する。
- 訪問先一覧のPDFも日本語を画像化し、標準欧文フォントへ日本語を渡さない。
- 明細が6行を超える場合は改ページする。手入力の金額・既存保存データ・APIキーは変更しない。

## 検証

架空の会社・日付・CSV・駐車場明細を使用する。外部Maps/Gemini APIを呼び出さない。
node --test tests/expense-import.test.cjs tests/expense-model.test.cjs
python3 -m http.server 8765 --bind 0.0.0.0

本番mainの変更と公開は、この修正ブランチの検証とは別に扱う。

## 残る確認

tests/expense-tests.html をローカルHTTPで開き「検証を実行」、2種類のPDFを出力し日本語と罫線を確認する。実際のETC CSVで列の認識・金額・枚数を照合する。変更前の下書きも読み込み確認する。
提出年がない旧明細は提出日の年として扱う。年をまたぐ旧下書きは利用日を確認する。
CSVの再取込識別は元の明細行を使う。異なる列構成・内容に変更されたCSVは同じ取込とは判定できない。
同じ日の別ルートを反映すると、その日の行先と距離を更新する。複数ルートの自動合算はしていない。

## 継続レビューの追加修正（2026-10-09）

旧駐車場データの移行は既存IDBの有無だけで移行元を削除せず、不足IDを取り込む。内容競合・保存失敗・移行中の旧データ変更では移行元を保持する。
距離再計算開始時には、その日の以前の計算結果を無効化する。再計算失敗後に古いキャッシュを使わない。既に精算へ反映した数値は自動削除しない。
駐車場保存失敗を成功表示せず、未保存の変更を戻す。削除はIDBトランザクション完了後に画面側を更新する。
手動追加の日付は端末のローカル日付を使用。サービスワーカーのキャッシュ名はv45に更新した。

`node --test tests/*.test.cjs`: 14本PASS（既存7本＋継続回帰7本）。JavaScript/CJS 31ファイルの構文と差分空白チェックPASS。
IndexedDBはNodeのモデルを使用。ブラウザから今回のローカルサーバーへの接続は拒否され、実ブラウザ・PDF視覚確認・タブレット表示は依然未確認。
