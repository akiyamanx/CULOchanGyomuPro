# 設定の分類と訪問編集中の操作 — 2026-10-19

## 目的と配置
訪問予約中のアカウント変更・接続解除の誤操作を避け、設定を1か所にまとめる。既存の色・入力欄・44px以上の操作領域を維持し、スマホでも分類を選んで操作する。

| 分類 | 内容 |
| --- | --- |
| Googleカレンダー | 接続、アカウント変更、接続解除、表示するカレンダー、初回設定・連携用ID |
| 地図・会社住所 | Maps APIキー、会社住所、設定保存、明示的な再読み込み |
| レシートのAI読取 | Gemini APIキー、設定保存 |
| バックアップ・データ管理 | 訪問先・ルート等の全対象月バックアップ／復元、現在の対象月の削除 |

訪問編集には予定・接続状態・更新・小さな設定入口を残す。未接続時は入口を「接続設定を開く」にする。全体の設定ボタンでは4分類を閉じた一覧、個別の入口では該当分類を開く。

## 操作上の契約
- 設定を開く間は元のダイアログを一時的に隠し、閉じたときに同じDOM・スクロール位置・入口フォーカスへ戻す。訪問編集の初期化や保存を呼び出さない。
- 日時・アポ状態・ルート・備考などの入力を保持。Googleのトークン・予定も設定の往復では変更しない。
- 接続中のアカウント変更、接続解除、接続中／認可中の連携用ID変更には確認を入れる。取消時は認証処理・保存・表示データを変えない。同じIDの再保存では接続を切らない。
- 設定は分類ごとに保存。未保存の入力を残して閉じる場合は破棄の確認を行う。保存失敗は入力を残して表示する。
- 地図APIキーの変更で自動再読み込みしない。入力中のダイアログがあるときは再読み込み・バックアップ復元・対象月削除を無効にする。復元と再読み込みには確認、削除には既存の件数付き確認画面を用いる。
- バックアップの既存仕様は変更せず、レシート画像・精算書を含まないことを明示する。
- 既存の保存キーを維持。トークン・Google予定はメモリだけ。AppStorageのprefix・専用IndexedDB・SW無効化を維持する。
- Google予定の読み取りスコープ、OAuthのクリック起点のポップアップ、取得取消・期限切れ・古い応答の無視を維持する。

- 390pxの地図拡大中も設定を開けること、実行時例外なし、設定の横はみ出しなしを確認。設定分類・カレンダー分類・訪問予定欄を目視確認。
- 専用プレビュー版を390pxで再検証し、設定の保存先が既存のprefix内だけであること、通常の設定入口、削除確認からの取消でもデータが残ることを確認。
